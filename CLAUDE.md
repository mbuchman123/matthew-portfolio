# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Matthew Buchman's personal portfolio site: a static HTML file (`index.html`) with inline CSS and inline JavaScript, an `assets/` folder of images, and one small data file, `videos.js` (the Content section's video/post list — see below). There is no build tool, package manager, framework, bundler, linter, or test suite — deployed by pushing to `main` on GitHub (`mbuchman123/matthew-portfolio`).

## Working in this repo

- **Preview**: open `index.html` directly in a browser, or serve the folder with any static file server. There is no dev server, no `npm run` scripts, and no `package.json` — don't add one unless asked.
- **Deploy**: pushing to `main` is the entire release process. There is no CI/build step. Commit and push directly.
- **Verify changes visually before pushing**: this is a design-heavy, layout-sensitive site (3D transforms, CSS Grid collapse animations, absolute positioning). Static review of the CSS is not enough to catch overlap/clipping/z-index bugs — actually render the page. The established pattern for this: set up Playwright in a scratch temp directory (`npm init -y && npm install playwright && npx playwright install chromium`), load `index.html` via a `file://` URL, screenshot the relevant state, and read the screenshot back. Several real bugs in this project's history were only caught this way (see Known gotchas below), not by reading the diff. For any change touching the shared mobile media query, check at a phone-width viewport (e.g. `viewport:{width:390,height:844}`) too, not just desktop — measure `scrollWidth`/`getBoundingClientRect()` against the viewport width for anything that might overflow, since a mobile override can silently fail to apply (see the media-query specificity gotcha below) without looking obviously wrong until you actually check the numbers.

## Architecture

Everything lives in `index.html` in three parts, in this order:
1. `<style>` in `<head>` — organized into commented sections (`/* HERO */`, `/* ABOUT */`, `/* EXPERIENCE CAROUSEL */`, `/* LEADERSHIP — STATIONARY TIMELINE */`, `/* CONTENT */`, `/* INTERESTS */`, `/* SKILLS */`, `/* CONTACT */`, `/* BUTTONS */`, etc.). CSS custom properties in `:root` define the brand palette (`--blue`, `--orange`, `--blue-bright`, `--bg`, `--surface`, `--muted`, `--border`). No CSS framework.
2. Markup in `<body>`, one `<!-- SECTION -->` comment block per page section, in the same order as the CSS sections and matching `id`s (`#hero`, `#about`, `#experience`, `#leadership`, `#content`, `#interests`, `#skills`, `#contact`).
3. `<script>` at the end of `<body>` — also organized by commented sections, matching the markup sections.

### The oversized gradient section title

Work Experience, Leadership & Development, Content, Interests, and Skills each open with a giant, low-opacity title (`.exp-bignum`, `.lead-bignum`, `.content-bignum`, `.interests-bignum`, `.skills-bignum`) instead of the small `.sec-pill`+`.sec-line` header the earlier sections (About, Contact) still use. It's the same recipe every time: `font-weight:800`, a `linear-gradient(to right, var(--orange), var(--blue))` clipped to the text (`background-clip:text` + `color:transparent` + the `-webkit-` duals), `opacity` around 0.26–0.38, `position:absolute`, centered, sitting *behind* the section's actual content by DOM order (it's an earlier sibling of a descendant that establishes its own stacking context — e.g. `.carousel-stage`'s `perspective`, or plain paint order — not by z-index). The content below is nudged down (`margin-top`/`padding-top` on the next element) just enough that the front card/photo/phone's top edge overlaps and covers the *bottom* of the letters — a deliberate layered-depth effect, not a bug to fix if you see it. Font size is tuned per phrase length so it stays on one line (~120px for "WORK EXPERIENCE", down to ~90px for the longer "LEADERSHIP & DEVELOPMENT") — don't reuse one section's font-size clamp for a differently-worded title without checking it still fits.

### Page sections and their interactive systems

- **Hero**: logo + nav links overlaid directly on the hero image (no separate nav bar). Background is a two-layer haze: `.site-haze` (`position:fixed`, spans every section, no fade) plus `.hero-haze` (more vivid, scoped to the hero, fades out via a CSS mask by the hero's own bottom edge). "Personal"/"Portfolio" headline text is split left/right to wrap around the portrait photo's head.
- **About**: two-column intro (`.about-row`) — a photo on the left (`.int-slot.about-photo-slot`, reusing the interests upload pattern/`lip()` handler) that's full-bleed to the true left edge of the viewport (this section drops `.section`'s left padding/max-width for exactly that reason, same as `.hero`) and fades out on its right/top/bottom edges via a two-layer CSS `mask-image` (`mask-composite:intersect`) into the text on the right (`.about-text`). No `.sec-header` — this section intentionally has no pill/line at all.
- **Work Experience**: a 3D coverflow carousel (`#exp-track` holds `.exp-card` elements). Position is a single continuous float, `expPos` (not an integer index) — `layoutCarousel()` derives every card's `translateX/translateZ/rotateY/scale/opacity` from its distance to `expPos`, and a `requestAnimationFrame` loop (`spinFrame`) advances `expPos` a little every frame while `spinning` is true, which is what makes the rotation read as a continuously-turning wheel rather than discrete steps — there's deliberately no CSS `transition` on `.exp-card`'s `transform`/`opacity` (a transition chasing an inline value that moves every 16ms just produces lag, not smoothness). Manual nav (arrows/dots/clicking a side card) calls `goToCard()` → `startSettle()`, which eases `expPos` to the target over a fixed `SETTLE_MS` (currently 380ms, cubic-out) rather than an unbounded asymptotic decay. Auto-spin runs continuously while the section is on screen (`startAutoSpin`/`pauseAutoSpin`/`scheduleResumeSpin`) and is **not** paused by hovering — only by dragging, opening a card, or manual nav, resuming after `RESUME_DELAY_MS`. Off entirely under `prefers-reduced-motion` (manual nav still works there, just snaps instead of easing). Clicking the front-and-center card (`cardClick(i, el, event)`) opens/closes its detail panel via `setCardOpen()` — the single place that toggles `.open`, snaps `expPos` to that exact card, and manages the auto-spin lock; used by both the card click and the "See details" button (`tx()`). Both `.exp-card`'s CSS transition list and `cardClick`'s `event.stopPropagation()` exist to dodge specific bugs — see Known gotchas.
- **Leadership & Development**: **not** a carousel/slider of full slides — the line, its 7 dots, and the nav are one stationary set of elements that never move or get rebuilt. `renderLeadership()` builds them once from the `LEADERSHIP` array (add/reorder/remove entries there — no `icon`/emoji field anymore, that was removed). `ltGoTo(i)` is what changes on navigation: the photo circle's `left` CSS-transitions along the fixed line to that entry's own fixed proportional position (inset 15%–85%, see Known gotchas), while the year/role/org/brief text does a quick fade-out → content swap → fade-in in place. Manual nav via `ltGoTo()`/`ltPrev()`/`ltNext()` — plus arrow keys while the section is in view, and two large hollow (`color:transparent` + `-webkit-text-stroke`, no fill) `‹`/`›` `.lt-side-arrow` buttons sitting directly on the left/right edges of the line itself (not below it) in the same bold font as the section's oversized gradient title. No auto-advance. Clicking the photo opens `#lt-modal` with the full bullet-point detail (`openLtModal(i)`/`closeLtModal()`) — the modal has a transparent backdrop (no page-dimming overlay) with a black-outlined inner box, the same popup treatment as the Interests modal below, not the usual dark-backdrop lightbox pattern.
- **Content**: pill-shaped, glassmorphic category selector (`.tab` — translucent-white/blurred when inactive, blue-gradient/white-text/lifted when active) replaces the old underline tabs; `switchTab(id, btn)` still just swaps `.tab-panel.active`, no reload. Cards are phone mockups (`.vid-card` — thick dark bezel border + a notch `::before`, aspect-ratio 9/16) floating directly on the page background — there is no dark box behind them (`.content-outer`/`.content-inner` carry no background/padding of their own anymore), so don't reintroduce white-on-dark button/text colors here, everything at the page level needs to read on the light site background (the video-card internals — title, tag, view count — keep light text since each card still has its own dark scrim regardless of page bg). Cards are **not** hardcoded — generated by `renderVideoTabs()` from the `VIDEOS` array in `videos.js` (loaded via `<script src="videos.js">` before the main inline `<script>`); see the comment at the top of that file for the object shape and the three statuses (`live`, `placeholder`, `soon`). Clicking a `live` card plays the video **inside that card's own phone screen** rather than in a separate lightbox — `playInCard(e,idx)` appends a full-cover `.vid-embed` div (containing the iframe plus a small `.vid-embed-close` ×) directly into the clicked `.vid-card`, at `z-index:5` — above the thumbnail/scrim but below the phone bezel's notch (`::before`, `z-index:6`), so the notch stays visually on top of the "screen" like a real phone. Embeds via a direct iframe (`tiktok.com/embed/v2/{id}` or `{instagram-url}/embed`) rather than the platforms' oEmbed `<script>` widgets, since those don't re-process cleanly when swapped in dynamically. Stops via the `.vid-embed-close` button, or `Escape` (`stopAllCardVideos()`, added to the shared Escape handler alongside `closeLtModal`/`closeInterestModal`) — there's no backdrop-click-to-close here since there's no backdrop, the card itself **is** the whole surface. Only one `.vid-card.playing` guard per card (clicking a card that's already playing is a no-op) — multiple cards can play simultaneously since each manages its own `.vid-embed`/`.playing` state independently; nothing auto-stops a different card's video when you start another one. Below the phones, `.social-row` is three glassmorphic link-out boxes (Instagram/TikTok/Facebook) with inline SVG/text icons — plain links, no JS.
- **Interests**: a bento/masonry grid (`.interests-grid`, CSS Grid with `grid-auto-flow:dense` and per-card `.int-card-lg`/`.int-card-tall` span classes), hardcoded per-card (not data-driven like Content/Leadership — there are only 6 tiles, so a data array wasn't worth it for the grid itself). All 6 tiles now have real photos (`assets/int-*.jpg`/`.webp`) and double up `.int-card` and `.int-slot` (the same upload-preview class as the About photo), which requires higher-specificity override rules (`.int-card.int-slot`, `.int-card.int-slot:hover`) — see Known gotchas for why plain `.int-card`/`.int-slot` rules alone aren't enough. Clicking a tile does **not** open the file picker directly the way `.int-slot` normally does elsewhere (About photo, Experience banners) — the `<input type="file">`/`.isi`/`.isl` "+ Add photo" markup was deliberately removed from these 6 cards and replaced with an `onclick="openInterestModal(i)"` on the card itself (index matches DOM order: Art, Sneakers, Content Creation, Bowling, Fitness & Health, Sports Statistics), so clicking anywhere on a tile opens `#interest-modal` instead — a short blurb (`INTERESTS_INFO[i].desc`, centered along with the title) plus a row of 3 `.im-upload` boxes. Each entry in `INTERESTS_INFO` can optionally carry a `photos:[...]` array (real `assets/` files) — `openInterestModal()` pre-fills any slot that has one (adding `.hp` and setting the `<img src>` directly) rather than leaving it as an empty "+ Add photo" prompt; a slot without a preset photo still falls back to the empty state. Per-interest `photoFit`/`photoPos`/`photoBg` fields control how a preset photo crops/positions/letterboxes (e.g. Sneakers uses `contain` so the whole shoe shows; Bowling/Art/etc. use `cover` to fill the box; Art's letterbox background is black). `.im-upload` reuses the exact `.int-slot` upload-preview pattern at a smaller size, with `limg()` as the modal-scoped twin of `lip()` (scoped to `.im-upload` instead of `.int-slot`) — and even a preset slot can still be swapped via the same file input, but like every other upload slot on the site that swap is a client-side-only FileReader preview and doesn't persist. Closes via the `.interest-modal-close` ×, clicking the backdrop (`e.target===this` check, not a global listener), or `Escape` (added to the existing shared Escape handler alongside `closeVideoModal`/`closeLtModal`). `.isi`/`.isl` (the "+ Add photo" placeholder text) are recolored white in `.int-card.int-slot` context since the shared base style assumes a light background, not this section's brand-gradient card background — that override is now also what the modal's `.im-upload` boxes fall back to using unscoped, since they sit on the modal's plain white surface.
- **Skills**: two rows (`#skills-row-Software`, `#skills-row-Professional`), one per category, each holding 5 `.skill-box` buttons built by `renderSkillBoxes()` from `SKILLS_BOOK` (name, category, `color` accent, `icon` — always a real logo `<img>` now, the inline-SVG icon path is legacy/unused — and an `usedIn` list of `{icon,role,org}`). Like Experience/Leadership/Content/Interests, the section opens with the oversized `.skills-bignum` gradient title. Compact state: no card background at all, just the floating logo (a `drop-shadow` filter stands in for a card shadow) with a plain-text name below it. Clicking a box **flips it in place like a trading card** at the same square footprint — it does not grow into a different shape or push its siblings around. `renderBoxHTML()` wraps each box's content in `.skill-flip` (`transform-style:preserve-3d`, rotated 180deg via `.skill-box.active .skill-flip`) containing two absolutely-stacked `.skill-face` panels: `.skill-front` (logo + name, what you see closed) and `.skill-back` (name + "used in" list, pre-rotated 180deg with `backface-visibility:hidden` so only one face is ever visible at a time). `.skill-box.img-icon.active` sets its own height/flex-grow to stay square rather than inheriting the taller/wider shape the generic `.skill-box.active` rule further up the stylesheet would otherwise give it. `.skill-back` centers its content both ways (`justify-content:center` + centered text) and still has `overflow-y:auto` as a fallback if a "used in" list is ever longer than the square has visual room for — the current sizing was tuned empirically against the longest list in the data (3 entries); if a skill gets a 4th, re-check that it still fits before assuming the CSS just works. Each `usedIn` entry's `icon` is a real org/leadership logo pulled from the matching Work Experience banner logo or Leadership timeline photo (falls back to an emoji only when neither exists, e.g. the Content Creator entry). No close button on the card — closing is click-anywhere-outside (a `document`-level listener checks `!activeBox.contains(e.target)`), clicking the active box again, or `Escape`; `openBox(i)`/`closeBox()` are the only two functions that touch `.active`. (Skills has gone through several designs historically — Skill Nebula → notebook page-flip → flower of petals → overlapping service-card rows → this trading-card flip — don't resurrect any of the earlier ones' functions/classes if you see them referenced in old comments elsewhere.)
- **Scroll crossfade**: `#hero`, `#about`, `#experience`, `#leadership`, `#content`, and `#interests` all carry a `.scroll-fade` class whose opacity/`translateY` are driven continuously by scroll position (`updateScrollFades()`, rAF-throttled, `fadeProgress()`) — reversible in both directions, unlike the one-time `.reveal`/`IntersectionObserver` fade-up still used by Skills/Contact. The fully-opaque "inner band" scales with each element's own height (`Math.max(vh*0.22, r.height*0.32)`), not just viewport height — without that, a section much taller than the viewport (e.g. Experience, heading well above the carousel) would start fading the instant you'd scrolled enough to center the carousel instead of the section's raw midpoint, since the two can't both sit at that midpoint at once. `#content` keeps **both** `.reveal` and `.scroll-fade` simultaneously — `.scroll-fade`'s inline styles override `.reveal`'s stylesheet-driven opacity entirely, but `.reveal`'s `IntersectionObserver` still adds `.visible`, which the granular vid-card stagger CSS (`.reveal.visible .vid-card`) still depends on. `#about`'s photo and text fade in with a slight stagger (photo first) via an offset in the same progress calculation, not a separate observer. Off (sections just stay visible, no motion) under `prefers-reduced-motion`.
- **Global**: a single `document`-level click listener closes any open experience card — clicking anywhere (inside the box or outside it) closes it, except the `.xbtn`/upload buttons, which call `event.stopPropagation()` so they don't fight this listener. (Leadership has no equivalent click-away-close — its detail view is the `#lt-modal` lightbox, closed via its own backdrop click/×/Escape.)

### Mobile responsiveness

All mobile-specific overrides live in **one shared `@media (max-width:720px)` block** (not one block per section) — when adding a new mobile fix, add it into that existing block rather than opening a new media query. Desktop CSS is written first/unconditionally and is meant to stay completely untouched by mobile work; mobile-only behavior (e.g. the hero nav wrapping onto its own row instead of a hamburger menu, the Work Experience carousel's "open" detail panel stacking below the card instead of beside it, `layoutCarousel()`'s per-card spacing scaling down via `expSpacing()`) is added as override rules/JS branches, not by editing the desktop rule in place. See the matching Known gotcha below before assuming a mobile override you just added is actually taking effect.

### Image handling

Every photo slot (`.banner-photo`, `.lt-photo-circle img`, `.ps`/`.int-slot` grids, including the About photo) has a hidden `<input type="file">` wired to `lb()`, `lp()`, or `lip()`. These are **client-side-only FileReader previews** — they swap the `<img src>` to a data URL in the visitor's own browser session and do not persist anywhere. To actually change a photo for all visitors, add the image file to `assets/` and update the `src` in `index.html` directly.

## Known gotchas (from this project's history)

- **`assets/` must stay lowercase.** The folder was once accidentally tracked in git as `Assets` (capital A). Windows is case-insensitive so this was invisible locally, but GitHub Pages hosting is case-sensitive — every image reference (`assets/...`) would 404 in production. If you ever rename/recreate the assets folder, verify with `git ls-files | grep -i assets` that it's tracked lowercase.
- **`@keyframes` names are global.** Two different sections once both defined `@keyframes fadeUp` with different bodies; the later declaration in the file silently won for *every* element using `animation: fadeUp`, including ones that needed a different transform. Give new keyframes unique, section-specific names rather than a generic shared one.
- **CSS Grid `0fr`→`1fr` collapse animations don't zero out height for children with an explicit fixed width.** A child like `width: 290px` inside a collapsing grid track still reports its full natural height even at zero visible width, inflating the parent row. Fix: explicitly toggle `height: 0; overflow: hidden` → `height: auto; overflow: visible` on that child alongside the width transition, don't rely on the grid track collapse alone.
- **`setPointerCapture` on a drag handler can hijack unrelated clicks.** Capturing the pointer on `pointerdown` anywhere inside a container redirects that pointer's `mouseup`/`click` to the capturing element regardless of where the cursor is, breaking normal `onclick` handlers on descendants. Only capture if you're actually tracking `pointermove`; a simple drag-distance check on `pointerdown`/`pointerup` doesn't need it.
- **A `position:absolute`/`fixed` element with an explicit (even `0`/negative) `z-index` can still paint above plain static siblings**, because CSS stacking-context paint order puts non-positioned in-flow content *before* positioned descendants at the same level. If a fixed/absolute background layer is supposed to sit behind normal page content, give it a **negative** `z-index`, not `0`.
- **Uploaded images often arrive duplicated.** The user's chat client doesn't give this tool direct file access to pasted images — the user saves them to disk (sometimes to the repo root instead of `assets/`, sometimes *also* uploading the same file directly via GitHub's web UI). Expect `git push` to occasionally be rejected because of a remote-only "Add files via upload" commit; `git fetch`, diff/checksum-compare the files, and merge rather than force-pushing.
- **`left:X%; transform:translate(-50%)` positioning on a fixed-size element clips at the container edge.** The leadership slider positions each dot/photo along `.lt-line` this way; at `left:0%` or `left:100%`, half the (250px) photo circle's width extends past the container's `overflow:hidden` boundary and gets clipped. Fix: inset the usable position range (e.g. 15%–85%, not 0–100%) so the first/last stop's circle stays fully visible — don't assume `0%`/`100%` are safe just because they're valid percentages.
- **A click handler that opens something (`.open`, a modal, etc.) must call `event.stopPropagation()` if a same-tick ancestor listener closes it.** The global "close on any click" listener (see above) runs on every click via bubbling; a click that both opens an element *and* bubbles to that listener gets closed again in the same tick before you ever see it open. The existing `.xbtn`/upload buttons already stop propagation for this reason — `cardClick()` (Experience) needed the same fix when it started opening cards directly instead of only navigating.
- **Two single-class rules on the same element (e.g. `.int-card` and `.int-slot`) have equal specificity — whichever is later in the stylesheet wins, not whichever you "meant" to take priority.** When the Interests bento cards reused `.int-slot` (the About photo's upload-preview class) for their background/hover behavior, `.int-slot`'s plain light-blue placeholder background and its `:hover` scale-up silently beat the new `.int-card` brand-gradient background, because `.int-slot` happened to be defined later in the file. Fix: add an explicit combined-selector rule (`.int-card.int-slot`, `.int-card.int-slot:hover`) with two classes — that's strictly higher specificity and wins regardless of source order. Don't assume "I wrote this rule after, so it wins" without checking actual selector specificity.
- **A rule inside `@media (max-width:720px)` gets no specificity boost from being in a media query** — it only wins a same-specificity tie against an unconditional desktop rule if it's physically *later* in the file. The shared mobile block sits fairly early (before most section-specific CSS), so a mobile override for something defined further down the file (e.g. `.contact-split`, or `.hero-nav .nav-logo img` which is 2 classes deep) can silently lose to the desktop rule even though the media query "should" apply. Two real instances of this while making the site mobile-friendly: `.contact-split{grid-template-columns:1fr}` inside the mobile block did nothing because the unconditional `.contact-split{grid-template-columns:1fr 1fr}` was defined later in the file — fixed by scoping the mobile rule to `#contact .contact-split` (higher specificity, wins regardless of order); and a mobile `.nav-logo img{height:32px}` lost to the desktop `.hero-nav .nav-logo img{height:42px}` because the desktop selector had *more* classes, not just later position — fixed by matching the desktop selector's specificity (`.hero-nav .nav-logo img`) in the mobile rule too. When a mobile override silently doesn't apply, check both source order *and* specificity against the desktop rule for that exact property, don't assume the media query alone settles it.
