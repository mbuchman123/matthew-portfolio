# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Matthew Buchman's personal portfolio site: a static HTML file (`index.html`) with inline CSS and inline JavaScript, an `assets/` folder of images, and one small data file, `videos.js` (the Content section's video/post list — see below). There is no build tool, package manager, framework, bundler, linter, or test suite — deployed by pushing to `main` on GitHub (`mbuchman123/matthew-portfolio`).

## Working in this repo

- **Preview**: open `index.html` directly in a browser, or serve the folder with any static file server. There is no dev server, no `npm run` scripts, and no `package.json` — don't add one unless asked.
- **Deploy**: pushing to `main` is the entire release process. There is no CI/build step. Commit and push directly.
- **Verify changes visually before pushing**: this is a design-heavy, layout-sensitive site (3D transforms, CSS Grid collapse animations, absolute positioning). Static review of the CSS is not enough to catch overlap/clipping/z-index bugs — actually render the page. The established pattern for this: set up Playwright in a scratch temp directory (`npm init -y && npm install playwright && npx playwright install chromium`), load `index.html` via a `file://` URL, screenshot the relevant state, and read the screenshot back. Several real bugs in this project's history were only caught this way (see Known gotchas below), not by reading the diff.

## Architecture

Everything lives in `index.html` in three parts, in this order:
1. `<style>` in `<head>` — organized into commented sections (`/* HERO */`, `/* ABOUT */`, `/* EXPERIENCE CAROUSEL */`, `/* LEADERSHIP — STATIONARY TIMELINE */`, `/* CONTENT */`, `/* INTERESTS */`, `/* SKILLS */`, `/* CONTACT */`, `/* BUTTONS */`, etc.). CSS custom properties in `:root` define the brand palette (`--blue`, `--orange`, `--blue-bright`, `--bg`, `--surface`, `--muted`, `--border`). No CSS framework.
2. Markup in `<body>`, one `<!-- SECTION -->` comment block per page section, in the same order as the CSS sections and matching `id`s (`#hero`, `#about`, `#experience`, `#leadership`, `#content`, `#interests`, `#skills`, `#contact`).
3. `<script>` at the end of `<body>` — also organized by commented sections, matching the markup sections.

### The oversized gradient section title

Work Experience, Leadership & Development, Content, Interests, and Skills each open with a giant, low-opacity title (`.exp-bignum`, `.lead-bignum`, `.content-bignum`, `.interests-bignum`, `.skills-bignum`) instead of the small `.sec-pill`+`.sec-line` header the earlier sections (About, Contact) still use. It's the same recipe every time: `font-weight:800`, a `linear-gradient(to right, var(--orange), var(--blue))` clipped to the text (`background-clip:text` + `color:transparent` + the `-webkit-` duals), `opacity` around 0.26–0.38, `position:absolute`, centered, sitting *behind* the section's actual content by DOM order (it's an earlier sibling of a descendant that establishes its own stacking context — e.g. `.carousel-stage`'s `perspective`, or plain paint order — not by z-index). The content below is nudged down (`margin-top`/`padding-top` on the next element) just enough that the front card/photo/phone's top edge overlaps and covers the *bottom* of the letters — a deliberate layered-depth effect, not a bug to fix if you see it. Font size is tuned per phrase length so it stays on one line (~120px for "WORK EXPERIENCE", down to ~90px for the longer "LEADERSHIP & DEVELOPMENT") — don't reuse one section's font-size clamp for a differently-worded title without checking it still fits.

### Page sections and their interactive systems

- **Hero**: logo + nav links overlaid directly on the hero image (no separate nav bar). Background is a two-layer haze: `.site-haze` (`position:fixed`, spans every section, no fade) plus `.hero-haze` (more vivid, scoped to the hero, fades out via a CSS mask by the hero's own bottom edge). "Personal"/"Portfolio" headline text is split left/right to wrap around the portrait photo's head.
- **About**: two-column intro (`.about-row`) — a photo on the left (`.int-slot.about-photo-slot`, reusing the interests upload pattern/`lip()` handler) that's full-bleed to the true left edge of the viewport (this section drops `.section`'s left padding/max-width for exactly that reason, same as `.hero`) and fades out on its right/top/bottom edges via a two-layer CSS `mask-image` (`mask-composite:intersect`) into the text on the right (`.about-text`). No `.sec-header` — this section intentionally has no pill/line at all.
- **Work Experience**: a 3D coverflow carousel (`#exp-track` holds `.exp-card` elements). Position is a single continuous float, `expPos` (not an integer index) — `layoutCarousel()` derives every card's `translateX/translateZ/rotateY/scale/opacity` from its distance to `expPos`, and a `requestAnimationFrame` loop (`spinFrame`) advances `expPos` a little every frame while `spinning` is true, which is what makes the rotation read as a continuously-turning wheel rather than discrete steps — there's deliberately no CSS `transition` on `.exp-card`'s `transform`/`opacity` (a transition chasing an inline value that moves every 16ms just produces lag, not smoothness). Manual nav (arrows/dots/clicking a side card) calls `goToCard()` → `startSettle()`, which eases `expPos` to the target over a fixed `SETTLE_MS` (currently 380ms, cubic-out) rather than an unbounded asymptotic decay. Auto-spin runs continuously while the section is on screen (`startAutoSpin`/`pauseAutoSpin`/`scheduleResumeSpin`) and is **not** paused by hovering — only by dragging, opening a card, or manual nav, resuming after `RESUME_DELAY_MS`. Off entirely under `prefers-reduced-motion` (manual nav still works there, just snaps instead of easing). Clicking the front-and-center card (`cardClick(i, el, event)`) opens/closes its detail panel via `setCardOpen()` — the single place that toggles `.open`, snaps `expPos` to that exact card, and manages the auto-spin lock; used by both the card click and the "See details" button (`tx()`). Both `.exp-card`'s CSS transition list and `cardClick`'s `event.stopPropagation()` exist to dodge specific bugs — see Known gotchas.
- **Leadership & Development**: **not** a carousel/slider of full slides — the line, its 7 dots, and the nav are one stationary set of elements that never move or get rebuilt. `renderLeadership()` builds them once from the `LEADERSHIP` array (add/reorder/remove entries there — no `icon`/emoji field anymore, that was removed). `ltGoTo(i)` is what changes on navigation: the photo circle's `left` CSS-transitions along the fixed line to that entry's own fixed proportional position (inset 15%–85%, see Known gotchas), while the year/role/org/brief text does a quick fade-out → content swap → fade-in in place. Manual nav only (arrows/progress dots via `ltGoTo()`/`ltPrev()`/`ltNext()`, plus arrow keys while the section is in view) — no auto-advance. Clicking the photo opens `#lt-modal` with the full bullet-point detail (`openLtModal(i)`/`closeLtModal()`).
- **Content**: pill-shaped, glassmorphic category selector (`.tab` — translucent-white/blurred when inactive, blue-gradient/white-text/lifted when active) replaces the old underline tabs; `switchTab(id, btn)` still just swaps `.tab-panel.active`, no reload. Cards are phone mockups (`.vid-card` — thick dark bezel border + a notch `::before`, aspect-ratio 9/16) floating directly on the page background — there is no dark box behind them (`.content-outer`/`.content-inner` carry no background/padding of their own anymore), so don't reintroduce white-on-dark button/text colors here, everything at the page level needs to read on the light site background (the video-card internals — title, tag, view count — keep light text since each card still has its own dark scrim regardless of page bg). Cards are **not** hardcoded — generated by `renderVideoTabs()` from the `VIDEOS` array in `videos.js` (loaded via `<script src="videos.js">` before the main inline `<script>`); see the comment at the top of that file for the object shape and the three statuses (`live`, `placeholder`, `soon`). Clicking a `live` card opens the `#video-modal` lightbox (`openVideoModal`/`closeVideoModal`), embedding via a direct iframe (`tiktok.com/embed/v2/{id}` or `{instagram-url}/embed`) rather than the platforms' oEmbed `<script>` widgets, since those don't re-process cleanly when the modal's content changes dynamically. Below the phones, `.social-row` is three glassmorphic link-out boxes (Instagram/TikTok/Facebook) with inline SVG/text icons — plain links, no JS.
- **Interests**: a bento/masonry grid (`.interests-grid`, CSS Grid with `grid-auto-flow:dense` and per-card `.int-card-lg`/`.int-card-tall` span classes), hardcoded per-card (not data-driven like Content/Leadership — there are only 6 tiles and 2 are static "coming soon" placeholders, so a data array wasn't worth it). Real cards double up `.int-card` and `.int-slot` (the same upload-preview class as the About photo), which requires higher-specificity override rules (`.int-card.int-slot`, `.int-card.int-slot:hover`) — see Known gotchas for why plain `.int-card`/`.int-slot` rules alone aren't enough. `.isi`/`.isl` (the "+ Add photo" placeholder text) are recolored white here since the shared base style assumes a light background, not this section's brand-gradient card background.
- **Skills**: two rows of "service card" style boxes (`#skills-row-Software`, `#skills-row-Professional`), one per category, each holding 5 `.skill-box` buttons built by `renderSkillBoxes()` from `SKILLS_BOOK` (icon, category, `color` accent, "used in" role list). Like Experience/Leadership/Content/Interests, the section opens with the oversized `.skills-bignum` gradient title (see above) instead of a `.sec-pill`/`.sec-line` header, no separate intro line or category legend underneath it — `#skills{position:relative}` + `.skills-boxes{margin-top:112px}` gives the rows enough clearance below the bignum letters that they read as a separate, smaller heading rather than the usual bignum overlap treatment — Skills deliberately doesn't overlap its title the way Experience/Content/Interests do, since a second haze title sitting right under the first got visually cramped. `.skills-row-label`s ("Software"/"Professional") sit centered above each row as the only labeling — deliberately not the same thing as the separate floating Software/Professional legend a prior iteration had, which was removed on request; don't re-add a standalone legend. These labels reuse the `.skills-bignum` recipe (same `font-family`/`font-weight:800`/low `opacity` haze look) at exactly 1/4 the font-size (`clamp(23px,2.25vw,33px)` vs. the bignum's `clamp(90px,9vw,130px)`) and solid `var(--blue)` instead of the orange→blue gradient, since two full-size gradient titles stacked on one section would compete with the actual "SKILLS" bignum above them. Each row is a plain flex row (`.skills-row{display:flex;gap:14px;align-items:flex-end}`); every `.skill-box` is `flex:1 1 0` so all 5 in a row start equal width. Clicking a box doesn't open a side panel — the box itself is the destination: `.skill-box.active` grows via `flex-grow:2.4` and a fixed taller `height` (378px desktop) while its background swaps to a category gradient (`--active-grad`, set inline per box: a dark-blue diagonal gradient for Software, dark-orange for Professional — the same brand-color family used everywhere else on the site, not an arbitrary color); `.box-detail` (the "used in" list) fades in on its own `opacity` transition with a `transition-delay` so the text only appears once the box has mostly finished growing — no JS timing needed for that part. Text on the active gradient background reuses the shared `.sp-item`/`.sp-role`/`.sp-org` classes with `.skill-box.active` descendant-selector overrides for light-on-dark colors, the same reasoning as the Content section's video-card text always being light regardless of page background. **Two real layout bugs hit and fixed while building this — both worth knowing before touching the sizing**: (1) `.box-detail` must collapse to `max-height:0;overflow:hidden` when inactive, not just `opacity:0` — `opacity:0` alone still participates in the box's flex-column sizing, and the full-height invisible detail list was pushing the icon/name out of the visible compact box. (2) The active box's fixed height (378px desktop) was sized empirically to fit the longest "used in" list currently in the data (3 entries, measured at ~370px content height) — if a skill ever gets a 4th "used in" entry, bump this number (or convert to a measured/auto approach) or its content will silently clip via the box's `overflow:hidden`, there's no scroll fallback. On mobile the rows switch to `flex-direction:column` (one full-width box per line) — critically, `.skill-box` there also needs `flex:none` (not the desktop `flex:1 1 0`), because leaving `flex-shrink:1` active inside an auto-sized column flex container let the active (taller) box get shrunk back down to its own `min-height:60px` floor, clipping all its content; this was the third bug caught here and is exactly the kind of thing that only shows up by actually rendering a click, not by reading the CSS. Unlike the earlier flower design's absolutely-positioned, physically-overlapping petals, plain flex siblings never overlap each other's hit-area, so every box — in either row — stays directly clickable even while a different one is active: clicking switches the active index directly, no close-then-open step needed. Closing still has the usual redundant paths: click the active box itself (`openBox` toggles closed on the same index), its `.box-close` × (`event.stopPropagation()` first, same reason as the Experience cards' `.xbtn`), a click on the `#skills-boxes` container background (`e.target===e.currentTarget` check, not a global document listener), or `Escape`. Arrow-key left/right cycles the active box while one is open, matching Experience/Leadership's in-view arrow-key convention. (Interests used to live in this section as an accordion — it's since been pulled out into its own `#interests` section above; don't go looking for `ti()`/`addLink()`, they were removed along with it. Skills has now gone through four designs — "Skill Nebula" radial diagram → spiral notebook page-flip → flower of petals → these overlapping service-card rows — don't resurrect `tskill`/`cskill`/`layoutNebula()`, `nbNext`/`nbPrev`/`nbGoTo`/`renderSkillPageHTML`, or `renderFlower`/`openPetal`/`closePetal`/`.flower-*`/`.petal-*`, all fully removed.)
- **Scroll crossfade**: `#hero`, `#about`, `#experience`, `#leadership`, `#content`, and `#interests` all carry a `.scroll-fade` class whose opacity/`translateY` are driven continuously by scroll position (`updateScrollFades()`, rAF-throttled, `fadeProgress()`) — reversible in both directions, unlike the one-time `.reveal`/`IntersectionObserver` fade-up still used by Skills/Contact. The fully-opaque "inner band" scales with each element's own height (`Math.max(vh*0.22, r.height*0.32)`), not just viewport height — without that, a section much taller than the viewport (e.g. Experience, heading well above the carousel) would start fading the instant you'd scrolled enough to center the carousel instead of the section's raw midpoint, since the two can't both sit at that midpoint at once. `#content` keeps **both** `.reveal` and `.scroll-fade` simultaneously — `.scroll-fade`'s inline styles override `.reveal`'s stylesheet-driven opacity entirely, but `.reveal`'s `IntersectionObserver` still adds `.visible`, which the granular vid-card stagger CSS (`.reveal.visible .vid-card`) still depends on. `#about`'s photo and text fade in with a slight stagger (photo first) via an offset in the same progress calculation, not a separate observer. Off (sections just stay visible, no motion) under `prefers-reduced-motion`.
- **Global**: a single `document`-level click listener closes any open experience card — clicking anywhere (inside the box or outside it) closes it, except the `.xbtn`/upload buttons, which call `event.stopPropagation()` so they don't fight this listener. (Leadership has no equivalent click-away-close — its detail view is the `#lt-modal` lightbox, closed via its own backdrop click/×/Escape.)

### Image handling

Every photo slot (`.banner-photo`, `.lt-photo-circle img`, `.ps`/`.int-slot` grids, including the About photo) has a hidden `<input type="file">` wired to `lb()`, `lp()`, or `lip()`. These are **client-side-only FileReader previews** — they swap the `<img src>` to a data URL in the visitor's own browser session and do not persist anywhere. To actually change a photo for all visitors, add the image file to `assets/` and update the `src` in `index.html` directly.

## Known gotchas (from this project's history)

- **`assets/` must stay lowercase.** The folder was once accidentally tracked in git as `Assets` (capital A). Windows is case-insensitive so this was invisible locally, but GitHub Pages hosting is case-sensitive — every image reference (`assets/...`) would 404 in production. If you ever rename/recreate the assets folder, verify with `git ls-files | grep -i assets` that it's tracked lowercase.
- **`@keyframes` names are global.** Two different sections once both defined `@keyframes fadeUp` with different bodies; the later declaration in the file silently won for *every* element using `animation: fadeUp`, including ones that needed a different transform. Give new keyframes unique, section-specific names rather than a generic shared one.
- **CSS Grid `0fr`→`1fr` collapse animations don't zero out height for children with an explicit fixed width.** A child like `width: 290px` inside a collapsing grid track still reports its full natural height even at zero visible width, inflating the parent row. Fix: explicitly toggle `height: 0; overflow: hidden` → `height: auto; overflow: visible` on that child alongside the width transition, don't rely on the grid track collapse alone.
- **`setPointerCapture` on a drag handler can hijack unrelated clicks.** Capturing the pointer on `pointerdown` anywhere inside a container redirects that pointer's `mouseup`/`click` to the capturing element regardless of where the cursor is, breaking normal `onclick` handlers on descendants. Only capture if you're actually tracking `pointermove`; a simple drag-distance check on `pointerdown`/`pointerup` doesn't need it.
- **A `position:absolute`/`fixed` element with an explicit (even `0`/negative) `z-index` can still paint above plain static siblings**, because CSS stacking-context paint order puts non-positioned in-flow content *before* positioned descendants at the same level. If a fixed/absolute background layer is supposed to sit behind normal page content, give it a **negative** `z-index`, not `0`.
- **Uploaded images often arrive duplicated.** The user's chat client doesn't give this tool direct file access to pasted images — the user saves them to disk (sometimes to the repo root instead of `assets/`, sometimes *also* uploading the same file directly via GitHub's web UI). Expect `git push` to occasionally be rejected because of a remote-only "Add files via upload" commit; `git fetch`, diff/checksum-compare the files, and merge rather than force-pushing.
- **`left:X%; transform:translate(-50%)` positioning on a fixed-size element clips at the container edge.** The leadership slider positions each dot/photo along `.lt-line` this way; at `left:0%` or `left:100%`, half the (250px) photo circle's width extends past the container's `overflow:hidden` boundary and gets clipped. Fix: inset the usable position range (e.g. 15%–85%, not 0–100%) so the first/last stop's circle stays fully visible — don't assume `0%`/`100%` are safe just because they're valid percentages.
- **A click handler that opens something (`.open`, a modal, etc.) must call `event.stopPropagation()` if a same-tick ancestor listener closes it.** The global "close on any click" listener (see above) runs on every click via bubbling; a click that both opens an element *and* bubbles to that listener gets closed again in the same tick before you ever see it open. The existing `.xbtn`/upload buttons already stop propagation for this reason — `cardClick()` (Experience) needed the same fix when it started opening cards directly instead of only navigating.
- **Two single-class rules on the same element (e.g. `.int-card` and `.int-slot`) have equal specificity — whichever is later in the stylesheet wins, not whichever you "meant" to take priority.** When the Interests bento cards reused `.int-slot` (the About photo's upload-preview class) for their background/hover behavior, `.int-slot`'s plain light-blue placeholder background and its `:hover` scale-up silently beat the new `.int-card` brand-gradient background, because `.int-slot` happened to be defined later in the file. Fix: add an explicit combined-selector rule (`.int-card.int-slot`, `.int-card.int-slot:hover`) with two classes — that's strictly higher specificity and wins regardless of source order. Don't assume "I wrote this rule after, so it wins" without checking actual selector specificity.
